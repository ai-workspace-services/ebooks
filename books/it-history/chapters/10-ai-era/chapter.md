### 一篇论文，点亮一座城

上一章，我们给自己留好了后路。现在，走进本书的终点站。

2017 年，一篇题为《Attention Is All You Need》的论文提出了 Transformer 架构。当时很少有人想到，它会成为整座 AI 城市的发电机。2020 年 GPT-3 发布，2021 年 GitHub Copilot 开始预览，2022 年 11 月 ChatGPT 上线——AI 第一次走进了普通人的日常。据瑞银（UBS）援引的第三方估算，它在上线约两个月后，月活跃用户就达到了一亿，被称为当时增长最快的消费级应用。2023 年 AutoGPT 等项目掀起 Agent 浪潮；2024 年 11 月，MCP 开放协议发布；2025 年，DeepSeek-R1 和 Claude Code 等编码 Agent 相继登场。

### 基础设施，重新回到舞台中央

其实，AI 和基础设施的这场重逢，早在 2012 年就有了预兆。那一年，多伦多大学的 Alex Krizhevsky、Ilya Sutskever 和 Geoffrey Hinton 用两块 NVIDIA GTX 580 游戏显卡训练出的 AlexNet，在 ImageNet 图像识别比赛中大幅领先。显卡原本是给游戏画画面的，从那以后，它成了训练神经网络的主力。

为什么是显卡？因为画游戏画面和训练神经网络，在数学上惊人地相似：都需要把海量的数字同时做同样的乘法和加法。CPU 像几位能力很强的大学教授，什么题都会做，但一次只能做几道；GPU 像几千名小学生，每人只会做简单的乘法，可大家一起做，速度远远超过教授们。

NVIDIA 在 2007 年推出了 CUDA，让程序员可以用接近普通编程的方式指挥这几千名“小学生”。这个看似小众的工具，后来成了 AI 时代最重要的护城河之一。

而 AlexNet 能赢，也离不开另一样东西：数据。斯坦福大学李飞飞团队主导的 ImageNet，收集并标注了上百万张图片。算法、算力、数据，三样凑齐，深度学习的时代才真正开始。

前面几章里，基础设施一直在“往下沉”：虚拟化沉到硬件里，云把机房藏到 API 后面，Serverless 把服务器藏到最深处。很多人以为，基础设施会越来越不重要。

AI 把这个趋势掰了回来。训练和推理需要海量的 GPU、高速网络和能源，基础设施重新回到了舞台中央。

训练一个大模型，往往需要成千上万块 GPU 连续工作很长时间。这些 GPU 之间要不停地交换数据，网络慢一点，整体效率就大打折扣，所以高速互联成了和 GPU 同样关键的东西。机房的电力和散热也被推到了极限，不少新建的 AI 数据中心，开始在选址时把电力供应放在第一位。

兜兜转转六十年，那个被云藏起来的“机房”，又一次成了新闻主角。

### 卡脖子的不只是芯片：网络与显存

训练大模型时，GPU 们不停地交换计算结果：每算完一步，就要把各自的梯度“对一下账”，这个动作叫 All-Reduce。NVIDIA 的 NCCL 通信库，就是专门给 GPU 们组织这种集体对账的。

同一台服务器里，GPU 之间走 NVLink，这条专用高速路 2014 年发布，2016 年随 Tesla P100 落地。跨服务器，就要靠 RDMA（远程直接内存访问）：让一台机器直接读写另一台机器的内存，不必劳烦双方的 CPU 和操作系统层层转手。

RDMA 主要有两条路。一条是 InfiniBand，专用网络，性能强，生态相对封闭；另一条是 RoCE，把 RDMA 跑在以太网上——2010 年的第一版只能在同一个二层网络里用，2014 年的 RoCE v2 加上了 UDP/IP 封装，可以跨三层路由。专用路和公路，各有拥趸，选哪一条，往往决定了一座 AI 机房的造价和运维方式。

训练难，推理也不轻松。大模型生成每一个字，都要回头看看前面所有的字，为了不重复计算，要把中间结果存起来，这就是 KV Cache。对话越长、同时服务的人越多，它占的显存就越大。

2023 年，伯克利团队在 SOSP 会议上发表了 vLLM 背后的 PagedAttention 论文。他们发现，按传统方式给 KV Cache 预留连续显存，大量空间被白白浪费；于是借鉴操作系统管理内存的“分页”办法，把它切成小块、按需分配。显存省下来了，同一块 GPU 就能同时服务更多请求。

几十年前操作系统发明的分页，在大模型推理里又回来了。基础设施的老智慧，从来不会真的过时。

### 一辆车背后的 AI 基座

以自动驾驶为例。一辆能自己开的车，背后不只是车上的芯片，还有一整套数据采集、训练集群、仿真和部署体系。车在路上跑，数据回到数据中心，训练出新模型，再发回车上——这是一个持续转动的飞轮。

这个飞轮里，最昂贵的往往不是芯片，而是数据的处理：海量的视频要被筛选、标注、去重，才能变成有用的训练素材。第 7 章讲的数据底座、专题一讲的数据家谱，在这里一下子变得非常具体——没有一条好用的数据管道，再强的算力也只能空转。

### AI 时代，还要懂开发吗？

有人会问：既然 AI 能写代码，我们还需要懂开发吗？这组“AI 时代需要掌握的开发基础知识”给出的回答是：要，但重点变了。你不必记住每一个语法细节，却需要看懂系统的边界，才能判断 AI 写得对不对。

这有点像有了计算器之后，我们仍然要学算术。不是为了比计算器算得快，而是为了在计算器给出一个离谱的数字时，能一眼看出“不对劲”。AI 写的代码能跑起来，不代表它是对的；能看出它哪里可能出错，才是新时代开发者真正的本事。

### 大模型到底在做什么

说了这么多，大模型的核心机制其实可以一句话讲完：根据前面的文字，预测下一个最可能出现的词。它一个词一个词地往下“接龙”，每一步都在一张巨大的概率表里挑选。

这听起来简单得有点不可思议，可当模型读过的文本足够多、参数足够大时，“接龙”就开始呈现出总结、翻译、写代码、推理的能力。Transformer 的“注意力”机制，让它在接龙时能回头看前文里所有相关的部分，而不是只盯着最近的几个字。

也正因为是“接龙”，它有时会一本正经地编出看似合理、实则不存在的内容，这被叫作“幻觉”。它并不是在撒谎，只是在概率上觉得“这句话接得很顺”。所以，越是重要的事实，越要让它给出处，越要人来核对。

Agent 则是在接龙之外，给模型配上了“手”：让它可以调用搜索、读写文件、执行代码、操作其他软件。模型负责想下一步做什么，工具负责真正去做，然后把结果再喂回给模型，如此循环。MCP 这样的协议，就是给这些“手”定一个统一的插头标准。

### 概率，与共同进化

最后，别忘了大模型的底色：它输出的是概率，而不是确定的真理。这既是它的创造力所在，也是它需要被验证的原因。
