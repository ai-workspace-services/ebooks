## 一、清晨的惊魂：计费大盘为何静默归零？

做独立开发出海 AI-SaaS，一个人就是一家运维团队。为了给全球用户最佳的低延迟体验，我们在多区域部署了边缘代理节点。今早醒来习惯性看后台，当场被一张图吓醒：

### 图 1：故障现场 · 控制台实时流量骤降为 0 B
![故障现场：控制台实时流量骤降为 0 B](img/01-incident-zero-traffic.png)

海外网络顺畅、代理转发毫无卡顿，但控制台实时流量卡片却**连续数小时死死定格在 0 B**！

这种“业务可用、计量失明”的现象被称为**幽灵断流**。计量一旦中断，计费脱节不说，异常突发更无法熔断。放以前，个人开发者只能苦哈哈逐台 SSH 登机敲命令看日志；但在 AI 时代，运维有了更优雅的解法。

## 二、前线探查：agent.guance.com 专家的只读审计

面对分散在各地的 6 台生产节点，我一条手工命令都没敲，直接唤醒了集群里的 **agent.guance.com 故障响应专家**。给它配上只读审计账号 `auditor` 和专用私钥 `/run/id_ed25519`，全权交给它自己去探。

### 图 2：前线感知 · 观测云 Agent 工作台自主穿透诊断
![前线感知：观测云 Agent 工作台自主穿透诊断](img/02-guance-obs-agent-investigation.png)

Agent 顺着 `Xray (:10086) ➔ Exporter (:8080) ➔ Vector (:8686) ➔ Billing` 链式下钻，没过几分钟就甩出了一份硬核推导：

### 1. 深度穿透与核心结论产出

#### 图 3：核心结论 · 故障响应专家穿透证据链
![核心结论：故障响应专家穿透证据链](img/02b-guance-agent-core-findings.jpg)

- **「全网 0 B」本质是前端差分退化**：实时值由相邻快照差值计算，断链后无新快照，差分归零。反证：东京节点实跑 14.57 GB，面板同样显示 0 B；
- **锁定真凶 `ph-xconnect.svc.plus`**：Vector 重启后表面 active，但缺配置未监听 8686，Exporter 24 小时被拒 522 次，属典型“服务 active ≠ 链路可用”假健康；
- **排查连锁隐患**：精准捕获第二 Xray 实例异常及节点批量重启致计数归零等盲区。

查完后，Agent 立马生成标准 `HANDOFF.md` 报告，顺畅交接给后方。

## 三、后方治理：Antigravity 契约根治与全网收敛

上线救火最忌讳“登机手工改配置”。接棒的 **Antigravity** Code Agent 根本不上机改 vim，而是直接动代码仓库，从根子上除病根：

### 图 4：后方行动 · Antigravity 代码治理与验收矩阵
![后方行动：Antigravity 代码治理与验收矩阵](img/03-antigravity-code-fix-and-audit.jpg)

Antigravity 治理干脆利落：
- **消除硬编码**：重构 Playbook 动态合并节点多域名，杜绝覆盖冲掉自定义配置；
- **自适应探测**：给 Vector 加入快照探测，无缝保留现有的 8686 监听与凭据；
- **OS级统一收敛（保留必要合并，清理多余残留）**：`ansible-pull` 在操作系统层同时兼容**非容器（轻量裸机）**与**容器（K8s）**两个版本，废除碎片化旧定时器，统一由 `pull_convergence.yml` 单原子自愈：
  1. `pull_gitops_declaration.yml`：自动检测并补充 `/etc/ansible-pull/` 目录与拓扑环境；
  2. `pull_flux_controller_limits.yml`：在无 kubectl 的轻量裸机上自动安全跳过，告别旧版 rc=2 崩溃，在容器节点收敛资源边界；
  3. `pull_observability_agent.yml`：自动收敛监控 Exporter 与 Vector 配置，去除子入口冗余重复调用；
  4. 全网清除旧服务残留与 systemd 缓存，杜绝假健康；
- **契约测试全绿**：跑通本地 13 项单元契约测试，将代码提交并推送至 GitOps 主干。
