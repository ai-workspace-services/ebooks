# 小红书笔记

## 标题
上线好好的，3天后崩了？2C4G小鸡压榨实录⚡️

## 正文
做独立开发和 AI-SaaS，谁手里还没几台 2C4G 的海外小 VPS？🥺
AMD 处理器，可用物理内存只有 3.8 GiB。上面挤着 K3s、PostgreSQL、Vault、Traefik、Flux CD，外加一堆 AI 业务容器。

每次发版，单元测试全过，探针返回 200 OK，你以为天下太平？
结果 72 小时后：
💥 没任何大并发，可用内存每天悄悄蒸发 150M，最后 Swap 占满主机死锁！
💥 凌晨根本没人用，后台证书控制器突然被内核 OOMKilled 重启！
💥 系统 CPU 隔几分钟就莫名锯齿抖动！

很多致命问题，**根本不是刚上线就能看到的**！
今天带大家拆解在真实生产节点（`prod-k3s-v6`）上抓出的**四大隐形刺客**：我们**如何发现？如何定位？又是如何彻底解决并净省近 400MB 内存的？** 直接抄作业👇

---

### 🔍 四大隐形刺客：
1️⃣ **Go Runtime 慢膨胀**：K3s Server 设了 `GOMEMLIMIT=1200M`，堆没到阈值迟钝不 GC，RSS 悄然吃掉 968MB，挂着 9,951 个 Goroutines，占去整机近 1/4 内存！
2️⃣ **64MB 悬崖惨案**：证书控制器平常只占 45MB，随手限配 64MB。结果每逢证书轮换瞬间冲到 65MB，刚好超标 1 兆，连续静默崩溃 17 次！
3️⃣ **GitOps 高频空转**：6 个仓库设 1 分钟轮询，每分钟拉取解包，双核 CPU 规律剧烈抖动；并发未限流导致内存突发尖刺。
4️⃣ **闲置组件吃空饷**：未配外部通知的 notification-controller 孤悬后台，天天白白常驻 33MB！

---

### 🛠️ 怎么破？三步闭环：发现 ➔ 定位 ➔ 解决

#### 1. 如何发现？（突破上线假象）
- 靠瞬时看盘永远是 200 OK！我们通过 **观测云（Guance Cloud）** 一体化轻量 DataKit 采集：
- **DQL 一阶导数计算**：`derivative(memory_working_set_bytes, 1h)` 发现 K3s 内存斜率连续 24 小时为正，宿主机可用空间阶梯下滑；
- **事件时间轴叠加**：在容器大盘开启关联事件，发现密密麻麻的鲜红圆点，当场捕获 17 次 OOM 离散崩溃！

#### 2. 如何定位？（穿透证据链）
- 点击 OOM 事件红点，右侧直接滑出当时的 dmesg 内核日志与证书轮换记录，实测峰值刚好 **65.2 MiB**，直接坐实 64M 配额过紧；
- 采集 Go Runtime 指标 `alloc_bytes` (666M) 与 `heap_inuse` (732M)，发现是环境变量 `GOMEMLIMIT=1200M` 门槛过高导致 Go 分配器惰性滞留内存。

#### 3. 如何辅助解决？（平滑自愈，业务 0 中断！）
- **配额与节流**：证书控制器 Limit 上调至 128M（实测 0 重启）；Flux 注入 `--concurrent=2` 并将轮询由 1m 延长至 5m（削减 80% 同步抖动）；缩容闲置控制器（立省 33M）。
- **零中断平滑自愈脚本**：编写 `/usr/local/bin/safe-k3s-mem-restart.sh`，利用 systemd 的 `KillMode=process`！杀控制面时，宿主机上正在跑的所有业务 Pod **绝对不被杀**！13 秒内 API 就绪，业务请求全程 0 掉线！
- 固化参数 `GOMEMLIMIT=768MiB`、`GOGC=50`，激进化垃圾回收。

📊 **实测战报**：
- K3s 进程内存从 955MB 暴降到 601MB（净释放 354MB！）
- Goroutines 从 9,951 砍半到 4,564
- 宿主机可用空间（Available）提升 25%，突破 1.25GB 安全线
- 11 个 Kustomization 与 8 个 Helm 全部 100% Ready！

---

### 🎯 以后这类问题怎么选告警？
牢记 3 条黄金法则：
1. **看斜率（趋势预测）**：`predict_linear` 提前 2 小时发现慢泄漏；
2. **抓离散（OOM 捕获）**：监控 `k8s_event` 中 `Reason == "OOMKilled"`，发生一次即报警；
3. **看可用（安全余量）**：只监控真实可调度的 `MemAvailable < 12%`，过滤无害缓存！
